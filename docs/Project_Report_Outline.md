# โครงร่างรูปเล่มปริญญานิพนธ์/โครงงาน (5 บท)
**ชื่อโครงงาน:** ระบบศูนย์ปฏิบัติการรักษาความปลอดภัยทางไซเบอร์อัจฉริยะ (Intelligent Security Operations Center - AI-driven SIEM & Honeypot Dashboard)

---

## บทที่ 1: บทนำ (Introduction)
**1.1 ที่มาและแรงจูงใจในการสร้างระบบ (Motivation)**
- อธิบายถึงภัยคุกคามทางไซเบอร์ในปัจจุบันที่มีความซับซ้อนและมีปริมาณมาก
- **ปัญหา (Pain Point):** ระบบเฝ้าระวังแบบเดิมมีข้อมูล Log มหาศาลและซับซ้อน ทำให้เจ้าหน้าที่ (SOC Analyst) เกิดภาวะ Alert Fatigue วิเคราะห์ได้ช้าและตอบสนองไม่ทัน
- **ความจำเป็น:** จึงต้องสร้างระบบที่นำ SIEM/Honeypot มาใช้ร่วมกับเทคโนโลยีปัญญาประดิษฐ์ (AI/LLM) เพื่อเป็นผู้ช่วยสรุปและวิเคราะห์ภัยคุกคามแทนมนุษย์

**1.2 ความแตกต่างจากระบบทั่วไป (System Differentiators)**
- **ระบบอื่นในตลาด:** มักมีอินเทอร์เฟซที่ซับซ้อน ใช้งานยาก ต้องอาศัยผู้เชี่ยวชาญในการเขียน Rule หรือวิเคราะห์ Log ด้วยตนเอง และระบบสำเร็จรูปมักมีราคาแพง
- **ความโดดเด่นของระบบเรา:** 
  1. **AI-Powered:** มี Generative AI เป็นแกนหลัก ช่วยย่อย Log ดิบให้เป็น Executive Summary แบบภาษามนุษย์อัตโนมัติ
  2. **Custom UI (Command Center):** ออกแบบหน้าจอแดชบอร์ดเฉพาะเจาะจง ให้สวยงาม ดึงดูด และจับจุดโฟกัสภัยคุกคามได้ง่าย (เช่น Global Threat Map)
  3. **Enterprise Integration:** เชื่อมต่อระบบยืนยันตัวตนระดับองค์กร (KKU SSO) ได้อย่างไร้รอยต่อ

**1.3 วัตถุประสงค์ของโครงงาน**
- เพื่อพัฒนาระบบแดชบอร์ดศูนย์ปฏิบัติการรักษาความปลอดภัย (SOC Dashboard) ที่สามารถแสดงผลข้อมูลภัยคุกคามทางไซเบอร์ได้แบบทันท่วงที (Real-time)
- เพื่อบูรณาการระบบ AI (Generative AI) เข้ามาช่วยในการแปลผล Log, สรุปสถานการณ์ (AI Briefing) และให้คำแนะนำการรับมือ
- เพื่อรวบรวมและแสดงผลข้อมูลจากระบบป้องกัน (Wazuh/SIEM) และระบบหลอกล่อ (Honeypot) ให้อยู่ในหน้าจอเดียวที่สวยงามและใช้งานง่าย

**1.4 ขอบเขตของโครงงาน**
- **ฝั่งผู้ใช้งาน (Frontend):** พัฒนาด้วย SvelteKit รองรับการแสดงผลแบบ Dashboard, Global Threat Map, MITRE ATT&CK Matrix, และ AI Briefing
- **ฝั่งเซิร์ฟเวอร์ (Backend):** พัฒนาด้วย NestJS เชื่อมต่อฐานข้อมูล PostgreSQL เพื่อประมวลผลข้อมูลและให้บริการ REST API
- **การเชื่อมต่อ AI:** มีการเชื่อมต่อกับ LLM API (เช่น Claude หรือ Gemini) สำหรับฟีเจอร์ AI Briefing และสืบค้นข้อมูลช่องโหว่ (CVE)
- **การยืนยันตัวตน:** รองรับการล็อกอินผ่านระบบ KKU SSO และ Local Authentication

**1.5 ประโยชน์ที่คาดว่าจะได้รับ**
- ทำให้องค์กรมีระบบเฝ้าระวังที่สามารถตอบสนองต่อภัยคุกคามได้รวดเร็วขึ้น
- ลดภาระงานของเจ้าหน้าที่ด้วยการให้ AI ช่วยคัดกรองและสรุปแจ้งเตือน (Alert Fatigue Reduction)
- เป็นต้นแบบสำหรับระบบ SOC สมัยใหม่ที่ขับเคลื่อนด้วยข้อมูลและ AI (Data-Driven & AI-Driven SOC)

## บทที่ 2: ทฤษฎีและเทคโนโลยีที่เกี่ยวข้อง (Literature Review)
**2.1 ระบบตรวจจับและป้องกันภัยคุกคาม (SIEM และ Honeypot)**
- หลักการทำงานของ SIEM (Security Information and Event Management) เช่น Wazuh
- หลักการของ Honeypot ระบบหลอกล่อและเก็บข้อมูลผู้โจมตี

**2.2 กรอบการทำงาน MITRE ATT&CK Framework**
- อธิบายถึง TTPs (Tactics, Techniques, and Procedures) และการนำมาจัดหมวดหมู่ภัยคุกคามเพื่อการวิเคราะห์

**2.3 เทคโนโลยีปัญญาประดิษฐ์เชิงรู้สร้าง (Generative AI & LLM)**
- บทบาทของ LLM ในงานด้าน Cybersecurity (เช่น การอ่าน Log, การวิเคราะห์ CVE, และระบบ AI Briefing)

**2.4 เครื่องมือและเฟรมเวิร์กที่ใช้ในการพัฒนา**
- **SvelteKit:** โครงสร้างการพัฒนา Frontend แบบ SSR, สาเหตุที่เลือกใช้ (ความเร็ว, การจัดการ DOM)
- **NestJS:** โครงสร้างสถาปัตยกรรม Backend เชิงวัตถุ (OOP) แบบโมดูล
- **TypeORM & PostgreSQL:** การจัดการฐานข้อมูลเชิงสัมพันธ์
- **Leaflet.js:** การแสดงผลแผนที่ (Global Threat Map)

## บทที่ 3: วิธีการดำเนินงานและการไหลของข้อมูล (Methodology & Data Flow)
**3.1 สถาปัตยกรรมระบบและการไหลของข้อมูล (Architecture & Data Flow)**
- อธิบายว่าข้อมูลถูกดึงมาจากไหนและนำไปใช้อย่างไร:
  1. **Data Sources (การดักจับ):** ข้อมูลเกิดจากระบบ Honeypot ที่เปิดล่อแฮกเกอร์ หรือจาก Endpoint ที่ฝังเอเจนต์ไว้
  2. **Aggregation (การรวบรวม):** Wazuh SIEM ทำหน้าที่ดูด Log ดิบจากแหล่งต่างๆ มารวมไว้ที่ส่วนกลาง
  3. **Processing (การประมวลผล):** Backend (NestJS) ทำการดูดข้อมูลจาก Wazuh มาจัดฟอร์แมต, ส่งไปวิเคราะห์ด้วย AI, และจัดเก็บลง PostgreSQL
  4. **Visualization (การนำไปใช้งาน):** Frontend (SvelteKit) ดึงข้อมูลมาแสดงผลบน Web Browser ให้เจ้าหน้าที่ล็อกอินผ่าน SSO เข้ามาตรวจสอบได้ทุกที่ทุกเวลา

**3.2 การออกแบบฐานข้อมูล (Database Design)**
- Entity Relationship Diagram (ER Diagram) ของตารางหลัก เช่น `users`, `attacks`, `login_sessions`, `api_logs`

**3.3 การออกแบบส่วนติดต่อผู้ใช้งาน (User Interface & UX Design)**
- แนวคิดการออกแบบแบบ "Command Center" (Dark theme, Glassmorphism, Neon Accents)
- โครงสร้างหน้าต่างและการจัดวาง (Layout Structure) ของแต่ละหน้า
  - หน้า Monitor Dashboard (Threat Map, Security Logs, Top Attackers)
  - หน้า AI Briefing
  - หน้า MITRE ATT&CK Matrix

**3.4 การบูรณาการ AI Backend Integration**
- กระบวนการรับส่งข้อมูลระหว่างระบบกับ LLM (Prompt Engineering)
- การประมวลผลข้อมูล Log ดิบให้เป็นสรุปสถานการณ์

## บทที่ 4: ผลการดำเนินงาน (Results & Implementation)
**4.1 ผลลัพธ์ส่วนหน้าจอหลักและระบบศูนย์ปฏิบัติการ (SOC Monitor)**
- ภาพประกอบและคำอธิบายหน้า Global Threat Map และ Live Alerts Feed
- การแสดงผลข้อมูล Top Attackers และ Target Ports ด้วย Progress Bars
- แผงควบคุม MITRE ATT&CK ที่นำข้อมูลจริงมาพล็อตกราฟิก

**4.2 ผลลัพธ์ส่วนระบบวิเคราะห์ด้วย AI (AI Briefing & Executive Summary)**
- ภาพประกอบหน้า AI Briefing ที่ทำการวิเคราะห์ข้อมูลภัยคุกคาม
- ผลลัพธ์ของการวิเคราะห์และการให้คำแนะนำในการตั้งรับ

**4.3 ผลลัพธ์ระบบความปลอดภัยของระบบและการยืนยันตัวตน**
- หน้าการเชื่อมต่อระบบ KKU SSO และหน้าจอบริหารจัดการผู้ใช้ (User Management)
- หน้าจอบันทึกประวัติการเข้าใช้งาน (Login Audit) และ API Log

**4.4 การแก้ไขปัญหาและเพิ่มประสิทธิภาพ (Performance & Bug Fixes)**
- การรับมือกับ SSR Error บน SvelteKit และโครงสร้าง Grid แบบตอบสนอง (Responsive Design) บนหน้า Monitor

## บทที่ 5: สรุปผลและข้อเสนอแนะ (Conclusion & Recommendations)
**5.1 สรุปผลการดำเนินงาน**
- สรุปว่าระบบสามารถตอบโจทย์วัตถุประสงค์ในบทที่ 1 ได้อย่างไร
- สรุปฟีเจอร์เด่นที่สามารถนำไปใช้ได้จริงในกระบวนการ SOC

**5.2 ปัญหาและอุปสรรคที่พบระหว่างการพัฒนา**
- ปัญหาที่พบเช่น การจัดการ Real-time data บน Frontend, การทำ Module Resolution (ปัญหา `$lib`), และความหน่วงในการประมวลผล LLM

**5.3 ข้อเสนอแนะและการพัฒนาต่อยอดในอนาคต**
- การเพิ่มแหล่งเชื่อมต่อข้อมูล Threat Intelligence ให้กว้างขึ้น
- การทำระบบ SOAR (Security Orchestration, Automation, and Response) เพื่อให้ระบบสั่งการ Block IP ผ่าน Firewall แบบอัตโนมัติ 
- การพัฒนาระบบ AI ให้เรียนรู้ข้อมูลและแจ้งเตือนพฤติกรรมผิดปกติได้อย่างแม่นยำยิ่งขึ้น
